# Magnetar — Architecture & shared contracts

Magnetar crawls Nostr relays for NIP-35 torrent events (kind 2003), stores and indexes them,
scores publishers with a web-of-trust, checks swarm liveness, and lets you search, inspect and
download from an Android app. A server (Postgres) and the phone (SQLite cache) both crawl; the
phone syncs what it finds up to the server.

This file is the **contract** between components. Research backing every decision lives in
`docs/research/*.md` (sources, live measurements, gotchas). When code and this file disagree,
fix one of them in the same change.

Semantics (both stores): results are **grouped by infohash** (canonical event); blocked publishers are
always excluded; `hide_dead` drops rows whose liveness is fresh and `best_peers()==0`; unknown is kept;
`min_seeders` treats unknown as 0 except when it is None; `sort=seeders` puts unknown last; the
empty query (no text, no source filter) lists a DHT-only torrent only once a seed check found
peers (D76, `SearchQuery::browse_hides_unchecked_dht`).
`core::query::fts5_match(text) -> Option<String>` and `pg_tsquery(text)` sanitize text (D11, D12).
The server answers from its Tantivy index once built (D43, docs/SEARCH.md); the SQL search of
D11 is the fallback, whose count stops at 1000 (`total_is_lower_bound`).

- `core`: unit tests on every fixture line in `docs/research/fixtures/` (parse, verify), deviation table
  cases, magnet, pow, bencode, UDP/HTTP scrape against in-process fake trackers, Bloom256 test vector
  (estimate ≈ 1224.93), trust formula table, negentropy sync against an in-process relay.
- `server`: integration tests against Postgres (`MAGNETAR_TEST_DATABASE_URL`): ingest fixtures, search
  filters/sorts, relay REQ, NIP-77 with nostr-sdk `Client::sync` as oracle, batch POST, auth; the
  search index (`tests/it/search_index.rs`: parity with the SQL search, text matching, updates within
  seconds, rebuild/resume, facets, a loose latency bound) and its 3 M benchmark
  (`tests/it/search_bench.rs`, `#[ignore]`, database from `scripts/bench-search-db.sh`, D43); the D44
  filters, facets, title view, backfill and notifier on both search paths (`tests/it/filters.rs`); D45
  seed checks against in-process trackers (`tests/it/liveness_pg.rs`: lanes, schedule, history,
  stats, API, index updates); D46 enrichers concurrently (`tests/it/enrich_anime.rs`); D47 breakdowns,
  series, health, graphs and their API (`tests/it/stats.rs`) and their timings on a production copy
  (`tests/it/stats_bench.rs`, `#[ignore]`).
- `core`: the release parser against a hand-checked sample of production titles with per-field
  floors (`tests/it/release_sample.rs`, D44).
- `ffi` (until D79, crate deleted): SqliteStore search parity with PgStore on the fixture set; cleanup never deletes unsynced rows;
  sync to a live in-process server; D44 filters, backfill and the offline title page (`tests/it/filters.rs`).
- Layout (D78): each crate's integration tests are modules of one binary, `tests/it/main.rs`
  (`tests/it/<former file>.rs`); one module runs with `cargo test -p <crate> --test it <module>::`.
- Network tests against real relays/trackers are `#[ignore]` (run with `--ignored`).
- `scripts/test.sh` = fmt check + clippy `-D warnings` + tests (with DB) + Android assembleDebug.
- CI (`.github/workflows/ci.yml`, D39) runs the same minus Android, against a `postgres:18` service.
