v0.3.1 (pre-release): crawl workers, the crawl map, a faster DHT engine, and a DHT crawler
that no longer overloads home routers (`main` at the `v0.3.1` tag). Update the server and the
app together; each side still works with an older other side.

## What's new

### The DHT crawler stays within what your router can take (ARCHITECTURE.md D109)

On a small home router, crawling at a modest `MAGNETAR_DHT_QPS` could still fill the router's
NAT table and cut the whole home network within seconds: the seed checker's DHT lookups and the
metadata downloads were not counted against the rate, and the router health probe reacted too
late and too gently.

- **One rate for everything.** `MAGNETAR_DHT_QPS` now covers the crawler *and* the seed
  checker's DHT lookups. With only seed checks running, they use the new
  `MAGNETAR_LIVENESS_DHT_QPS` (default 20).
- **Fewer TCP connections by default.** `MAGNETAR_DHT_TCP_RATE` now defaults to half of
  `MAGNETAR_DHT_QPS` (between 5 and 150) instead of a flat 150.
- **A router probe that reacts in seconds and can slow down further.** It checks every target
  every 2 s, reacts from the third sample, and each time the router looks saturated it cuts the
  DHT and TCP rates again (½, ¼, then ⅛), easing back after 5 calm minutes. It now also runs
  when only seed checks use the DHT, and keeps running while the crawler restarts.
- **On a small router**: keep `MAGNETAR_DHT_UPNP=false`, start low (for example
  `MAGNETAR_DHT_QPS=12`), and set `MAGNETAR_DOWNLOADS=false` if you do not download on the
  server: the download engine runs its own DHT node outside these limits.

### Crawl workers (docs/WORKERS.md, D96–D100)

Other machines can share the crawling from their own internet line: `magnetar-server worker`
takes a share of the seed checks and runs its own DHT crawler, and reports to the main server
over its API with a worker token (`MAGNETAR_WORKER_TOKENS` on the server). The main server keeps
the database, search and API.

### Where discoveries come from, and the crawl map (docs/CRAWLMAP.md, D101–D105)

Stats → Charts has a card showing where torrents come from (DHT routes, Nostr relays, each
crawling machine) and opens a world map of DHT discoveries and Nostr relays by country and
network. No IP address is ever stored, logged or sent to the app: addresses become country and
network counts in memory (DB-IP Lite databases, `MAGNETAR_GEOIP`).

### DHT engine

- Spread over CPU cores (one shard per virtual node), up to 32 virtual nodes and 20 000 q/s
  (D106).
- Lookups avoid nodes known not to answer (D95); the sampler no longer stalls on a small node
  pool (D108).

### Other

- The server raises its open-files limit at start.
- Docs: benchmark archive (docs/benchmarks/), roadmap (docs/ROADMAP.md).

## Upgrading

- New settings: `MAGNETAR_LIVENESS_DHT_QPS`, and the worker and crawl-map settings in
  docs/CONFIG.md. `MAGNETAR_DHT_TCP_RATE` has a new default; set it explicitly to keep 150.
- Docker: `compose.yml` passes the new settings; pull the new image or rebuild.
